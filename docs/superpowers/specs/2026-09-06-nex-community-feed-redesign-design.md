# NEX Community Feed Redesign — Design Spec

**Date:** 2026-09-06  
**Status:** Draft for Founder review (not implementation-approved until Founder confirms this file)  
**Owner:** Purple (product design)  
**Scope:** Community UX model shift — Reddit-style forum → SNS-style feed that still supports talk, track showcase, and discussion (A+B+C)

---

## 1. WHY

현재 `/community`는 Reddit형(카테고리 사이드바, upvote/하트 혼재, **트랙 첨부 필수**)이라 “쉽게 글 쓰고 반응하는 커뮤니티”로 읽히지 않는다.

NEX 본체는 AI Music Battle & Ranking이다. 커뮤니티는 두 번째 트랙 제출창이 아니라, **곡 옆에 붙는 사람 소리**(의도, 프롬프트, 배틀 토크, 가벼운 일상)여야 한다.

대표 목표: YouTube / SNS처럼 **글쓰기 · 댓글 · 좋아요 · 공유 · 피드**가 한눈에 이해되고, 동시에 트랙 자랑(B)과 토론(C)도 같은 공간에서 가능해야 한다.

---

## 2. CONTEXT (현재)

- 라우트: `/community`, `/community/:id` → `Community.tsx` (상세는 인피드 Dialog)
- 가능: 글·좋아요·댓글·공유, 카테고리 4종, 트랙/MV **필수** 첨부
- 없음: 글로벌 SNS 피드 모델, 팔로잉 타임라인, 통일된 반응 UX
- 혼란: upvote + Heart, 트랙 모달 댓글 vs 커뮤니티 댓글 이원화, 네비 다층
- 기존 WHY 시드: 트랙 제출과 분리된 토론 공간 (`shared/community.ts`) — **의도(토론)는 유지**, **형태(포럼 UI·트랙 필수)는 변경**

## 3. USER EXPERIENCE (잠정 확정)

### 3.1 한 줄 정의

**커뮤니티 = 하나의 최신 피드.**  
A(가벼운 글) + B(트랙 자랑) + C(토론)를 **메뉴 분리가 아니라 카드 타입**으로 품는다.

### 3.2 첫 화면

- 기본: **전체 최신 피드**
- 그 안에 트랙 포스트를 **살짝** 섞음 (별도 탭으로 B를 강제하지 않음)
- 콘텐츠가 적을 때 인위적 강제 삽입 없음 — 있는 글을 시간순으로
- 보조(이번 범위 이후): `팔로잉` 탭 (비어 있으면 최신/추천 폴백)
- 필터 칩: 트랙 · 프롬프트 · 배틀 · 도움말 (선택). 사이드바 카테고리 제거

### 3.3 글 카드

- 프로필 · 이름 · 시간 · (있으면) 태그/타입 뱃지(작음)
- 본문 + 더보기
- 트랙 있으면 같은 폭에 커버·제목·재생
- **텍스트 글과 트랙 글의 시각 비중은 거의 같게** (구분만 살짝)
- 하단 반응 **통일**: 좋아요 · 댓글 · 공유만
- upvote / downvote UI 제거

### 3.4 글쓰기

- CTA 하나 → **바로 텍스트 입력** (기본 타입 = 토크)
- 칩: `토크` · `트랙 자랑` · `토론`
- **트랙 첨부: 필수 아님** (초기 트래픽·유명도 고려). `트랙 자랑`에서도 텍스트만 게시 가능. UI 유도만 세게 (“붙이면 더 잘 보여요”)
- `토론`: 제목 + 본문 (포럼형 필드)
- 태그: 글쓰기에서 선택 또는 맥락 자동. 기존 카테고리 slug는 태그로 보존

### 3.5 댓글 · 알림 · 상세

- 커뮤니티 글 댓글 한 갈래 (대댓글 깊이 1단계면 충분)
- 글·댓글 모두 하트
- 알림 최소: 내 글 댓글/좋아요 (멘션은 이후)
- 상세: 공유·딥링크가 되는 상세(또는 시트). URL `/community/:id`와 UX 정합

### 3.6 기존 데이터

- 기존 글·좋아요·댓글 **삭제 없음** → 피드 카드 매핑
- 카테고리 → 태그
- upvote UI 제거 후 숫자는 좋아요로 정리
- 시드/가짜 폴백 글은 실서비스 피드에 노출하지 않음

## 4. WHAT / SCOPE

### In scope (v1 제품 방향)

| 항목 | 내용 |
|------|------|
| IA | 단일 피드 + 필터 칩 + 글쓰기 CTA |
| Compose | 토크 기본 / 트랙 자랑·토론 칩 / 트랙 비필수 |
| Reactions | 좋아요 · 댓글 · 공유 통일 |
| Cards | 텍스트 ≈ 트랙 시각 비중 |
| Migration | 기존 포스트 → 피드 카드, 카테고리→태그 |
| Detail | 딥링크 가능한 상세 UX |

### Out of scope (의도적, 이후)

- 팔로잉 탭 본격 구현
- DM, 스토리, 알고리즘 추천 홈
- 트랙 재생 모달 댓글 ↔ 커뮤니티 댓글 통합
- 멘션
- 트랙 첨부 필수로의 재전환 (트래픽 붙은 뒤 재논의)

## 5. HOW (구현 방향 — 설계 수준)

코드/스키마 변경은 **이 스펙 Founder 승인 + implementation plan 승인 후**에만 진행한다.

방향만:

1. UI: `Community.tsx` Reddit 레이아웃 → SNS 피드 리스트
2. Compose: 트랙 필수 validation 제거; post type = `talk` | `track` | `discussion`
3. API: 최신 피드 기본; `popular` 등은 필터/이후 탭용
4. Reactions: upvote UI 경로 제거, like 단일화
5. Seed fallback: production/empty 시 가짜 실글처럼 보이지 않게
6. 테스트: 비로그인 피드 조회, 로그인 텍스트-only 게시, 트랙 선택 게시, 좋아요/댓글/공유, 기존 글 매핑

상세 태스크·파일 단위 계획은 `docs/superpowers/plans/`에 writing-plans로 작성한다.

## 6. ACCEPTANCE TEST (제품)

1. `/community` 진입 시 **카테고리 포럼이 아니라 최신 피드**로 인식된다.
2. 로그인 사용자가 **트랙 없이** 짧은 글을 올릴 수 있다.
3. `트랙 자랑`에서 트랙을 붙이거나, 안 붙여도 게시된다 (유도 UI는 보인다).
4. 카드마다 좋아요·댓글·공유가 같은 자리에 있다. upvote UI가 없다.
5. 텍스트 글과 트랙 글의 카드 크기가 과하게 차이 나지 않는다.
6. 기존 실데이터가 피드에 보이며, 카테고리 정보가 태그로 남는다.
7. 시드 폴백이 실제 유저 글처럼 클릭/혼동을 만들지 않는다.
8. `/community/:id`로 공유·재진입이 가능하다.

## 7. Founder decisions (this thread)

| 주제 | 결정 |
|------|------|
| 욕심 범위 | A + B + C |
| 첫 화면 | 전체 최신 + 트랙 포스트 살짝 |
| 글쓰기 기본 | 짧은 토크 (퍼플 추천 A) |
| 트랙 필수 여부 | 아님 (유도만) — 초기 유명도·귀찮음 고려 |
| 카드 시각 비중 | 텍스트 ≈ 트랙 (A) |
| 정보 구조 | 단일 피드, 사이드바 카테고리 제거 |
| 문서화 | 본 스펙 작성 승인 (“가자”) |

## 8. Risks / Blue Review

- **욕심(A+B+C) vs 단순함:** 메뉴를 나누지 말고 카드 타입으로만 풀어야 다시 어지러워지지 않음.
- **트랙 비필수:** 음악 플랫폼 정체성과의 긴장 — 피드 믹스·트랙 자랑 칩·유도 UI로 B를 살리되, 초기는 글 양이 우선.
- **댓글 이원화 잔존:** v1에서 트랙 모달 댓글과 미통합 → 사용자 혼란 가능. 2차 과제임을 명시.
- **핵심 제품 방향 변경:** 커뮤니티 UX 모델 전환이므로 **구현·배포 전 Founder 최종 승인** 필요 (CBSU 게이트).
